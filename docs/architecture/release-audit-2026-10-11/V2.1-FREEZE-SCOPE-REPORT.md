## Escopo de execução medido neste código

`run-engine` (`orchestrator/src/cli/run-engine.ts`, `setupProviders`) registra `CursorSkillProvider` quando o manifesto é `cursor-skill` e existe `JobFileExecutor`. Qualquer outro id cai em `createMockProvider`. Essa função não registra `DeterministicProvider`.

`DeterministicProvider` existe na biblioteca e no `PluginLoader` para tipos `deterministic` e `shell`. Os testes unitários o constroem direto.

| Capacidade | Quem alcança | Isolamento medido no código | Autorização medida |
| --- | --- | --- | --- |
| CLI mock | `run-engine` sem manifesto `cursor-skill` | não executa o handler determinístico | não é execução real |
| `cursor-skill` | CLI com `--jobs-dir` ou discovery e manifesto desse tipo | executor de arquivo de job, sem bubblewrap neste módulo | fora do provider determinístico |
| `filesystem.read` / list / search | `DeterministicProvider` | confinamento de caminho em processo | leitura entra em `deterministic_read_only` |
| `filesystem.write` | idem | caminho em processo, sem sandbox de SO | exige `allowWrite` ou `confirmed`; sem isso, deny ou confirm |
| `shell.execute` | idem, com `allowShell: true` | `spawn` com `shell: true` e `env: { ...process.env }` no host | sem `allowShell`, o teste mediu falha (`CONFIRMATION_REQUIRED` ou `AUTHORITY_DENIED`). `confirmed: true` autoriza mesmo com `allowShell === false` |
| `git.*` | idem | `execFile("git")` no host | tratado como leitura |
| `system.inspect` | idem | `os` mais `execFile` de `df` e `ps` no host | o teste `system.inspect returns metrics` passou sem grant extra (876 ms) |
| `knowledge.*` | idem | `spawn("python")` com `env: { ...process.env }` | `isNetwork` ignora `knowledge.*`; sem flag de inspeção de host |
| Antigravity / `registerBuiltinBackends` | não há ocorrência em `orchestrator/src` | não aplicável neste tree | `NOT_APPLICABLE` |

`UNISOLATED_CAPABILITY_STATUS: BLOCKED`

Não há wrapper bubblewrap, Seatbelt nem outro sandbox de SO em `orchestrator/src`. Quando `shell.execute` é autorizado, o processo herda o ambiente do orquestrador.

`AUTHORIZATION_STATUS: PARTIAL`

Shell, escrita e rede sem flag ficam em confirmação ou negação. `confirmed` converte essa negação em allow. `system.inspect` e `git.*` seguem sem um grant específico de host. A CLI não instala um contexto somente leitura no engine.

## Evidência e DoD

`buildGateEvidence` mapeia veredito `passed` para `checks[].result = "pass"` e `spec.status = "complete"`. `buildSuccessEvidence`, para nó `gate`, chama esse builder com `"passed"`. `validateEvidenceV21` aceita a evidência quando cada DoD tem check `pass`, o status é `complete` e o veredito de gate não é `rejected`.

Neste código, um veredito de gate `passed` carimba os checks. Não há rejeição de evidência sintética ou simulada nesse validador.

`DOD_EVIDENCE_STATUS: BLOCKED`

## Checkpoint e rollback

`saveCheckpoint` grava JSON `kind: "EngineCheckpoint"` com `saved_at`. `loadCheckpoint` faz `JSON.parse` do arquivo. Não há HMAC, algoritmo, chave nem código de assinatura ausente.

Um arquivo editado ou substituído é aceito se o JSON parsear. Não há proteção contra restaurar um checkpoint antigo. Esta medição não implementou essa proteção.

`ROLLBACK_RISK: BLOCKED`

`CHECKPOINT_INTEGRITY: NOT_MEASURED` como propriedade criptográfica, porque o formato não tem autenticador para verificar.
