# Escopo proposto da V2.2

Isto é proposta para decisão. Não é ADR aceito e não foi implementado.

A V2.2 é a camada que torna o conhecimento **por projeto** operável e medível, e que escreve o ADR de ownership que a compaction futura precisa. Ela não é a V3.

## Fora de escopo

| Item | Destino |
|---|---|
| World Model, Belief/Observation, Agency, Governor, demos Meta 0 | V3 (`evolve-v3`) |
| Memory Trust em runtime | V3; schema já existe lá |
| Cost governor, roteamento de modelo, long-horizon 10k | V3 metas 7, 21, 22 |
| Sandbox de SO, HMAC já tratado na linha V2.1 à parte | Não misturar com wiki |
| Novo `KnowledgeBackendId`, LanceDB no processo TS | Rejeitado pelo ADR-0004 |
| GraphRAG, LightRAG, Graphiti, Mem0, Letta, claude-mem, Repomix, LLMLingua no hot path | Descartados ou só monitorados |
| `caveman-compress` em contrato/skill/código | Descartado |
| `--wiki` do Graphify, cloud Graphify, Neo4j obrigatório | Descartado na V2.2 |
| Serena dentro do repo MIT | Descartado (GPL-3.0-or-later na aplicação) |
| `max_skills` no engine | Continua adiado (ADR-DR-0002) até E-001-LIVE |
| Percentual fixo de economia como gate | Proibido até o baseline do arquivo 08 |

## P0 — Fundação

### P0-1 — ADR de ownership do contexto

| | |
|---|---|
| Problema | ADR-DR-0005 bloqueia compaction/reinject. A V3 também separa canais e ainda não responde o working context do host |
| Estado atual | Compaction `NOT_IMPLEMENTED`. Checklist de 9 perguntas em aberto de propósito |
| Resultado | ADR novo que responda as 9 perguntas. Proposta de conteúdo, sujeita a revisão humana: (1) contexto compactado de trabalho não tem store próprio permanente; (2) não é Memory; (3) não é Knowledge até verificação contra código ou decisão explícita; (4) não é Checkpoint; (5) a fronteira é a chamada ao modelo; (6) reconstrução lê checkpoint + memory da feature + páginas `.ai/` não obsoletas + arquivos; (7) reinject só entra se um teste de fidelidade passar; (8) perda aceitável é só prosa já coberta por evidência e páginas; paths, negações, comandos e DoD não se perdem; (9) para resume, sobrevivem grafo, evidência, decisões da feature e páginas `atual` |
| Solução | Documento em `docs/adr/`. Sem código de condenser |
| Dependências | Nenhuma ferramenta externa |
| Mudança de arquitetura | Nenhuma no runtime. Desbloqueia desenho futuro |
| Aceite | As 9 perguntas têm resposta explícita. Knowledge, Memory e Checkpoint continuam tipos distintos. Working context declarado descartável |
| Métricas | N/A (decisão). Não inventar percentual |
| Testes | Revisão do ADR contra ADR-DR-0005 e contra `WORLD-MODEL.md` da V3 para não criar segundo store |
| Riscos | Responder errado e liberar sumarizador cedo |
| Esforço | Baixo |
| Bloqueio | Se a resposta exigir fundir os três stores, parar |
| Concluída quando | ADR merged com status accepted ou explicitly rejected. Os dois fecham a pergunta; rejected mantém o defer |

### P0-2 — Cerca de raiz de projeto

| | |
|---|---|
| Problema | `feature_id` e `data-dir` não isolam dois repositórios. MCP memory e um grafo global misturariam |
| Estado atual | Não há detector de toplevel no engine. Wiki-carpaccio assume “o repositório” |
| Resultado | Regra escrita e testável: uma raiz = um `.ai/` = um cache de grafo. Sem git, a raiz é o path explícito. Submodule e `/tmp` não herdam wiki |
| Solução | Convenção + teste de fixture. Implementação mínima pode ser só a skill recusar init fora da raiz. Não precisa de serviço |
| Dependências | P0-1 não é pré-requisito lógico, mas evita discutir “onde mora o resumo” ao mesmo tempo |
| Mudança | Nenhuma em contrato público se a regra viver na skill e num teste de path |
| Aceite | Cenário 12 do plano: string canário do projeto A ausente do contexto do projeto B |
| Métricas | 0 vazamentos no fixture |
| Testes | Dois roots temporários |
| Riscos | Monorepo com vários produtos na mesma raiz precisa de páginas, não de várias wikis. Documentar isso |
| Esforço | Baixo |
| Bloqueio | Se a única forma de isolar for um banco multi-tenant novo, parar e ficar na skill |
| Concluída quando | O teste do canário existe e passa, e a skill recusa init em diretório temporário sem confirmação |

### P0-3 — Harness de medição

| | |
|---|---|
| Problema | E-001 não mede tokenizer de vendor nem sucesso de tarefa. Não dá para aceitar otimização |
| Estado atual | PROXY whitespace; `task_success NOT_MEASURED`; LLM live `NOT_MEASURED` |
| Resultado | Fixture + protocolo do arquivo 08, braço B0 executado uma vez, números publicados como baseline |
| Solução | Harness no estilo E-001 (raw JSON), com tokenizer nomeado |
| Dependências | Acesso a um modelo. Se não houver, o harness e o fixture ainda podem ser entregues, com resultado `NOT_MEASURED` — isso não conta como P0-3 concluído |
| Mudança | Nenhuma no runtime de produção |
| Aceite | Raw contém tokens de entrada/saída, paths, verificador, SHA do tree, id do modelo |
| Métricas | As do arquivo 08, preenchidas para B0 |
| Testes | Integridade do scorer, como `integrity_test.py` do E-001 |
| Riscos | Medir no Cursor sem controlar cache e achar um ganho irreproduzível. Registrar se o cache do host estava ligado: se for UNKNOWN, escrever UNKNOWN |
| Esforço | Médio |
| Bloqueio | Sem modelo e sem tokenizer, não promover P1 que prometa economia |
| Concluída quando | Baseline B0 está no repositório de evidência e os alvos da P1 foram escritos a partir dela, não antes |

P1 de economia não começa sem P0-3. P1 de wiki (continuidade) pode começar depois de P0-2, com tokens ainda `NOT_MEASURED`, desde que o critério seja o verificador e o canário, não um percentual.

## P1 — Entrega principal

### P1-1 — Wiki de projeto operada

| | |
|---|---|
| Problema | ADR-0004 e a skill existem; o agente não tem um fluxo obrigatório de init/query/update |
| Estado atual | Skill draft no host. Engine não cria `.ai/` |
| Resultado | Num projeto real de fixture: init mínimo, uma decisão com fonte, query que não lê a pasta inteira, update após mudança de comportamento, lint que marca a página velha |
| Solução | `wiki-carpaccio` como está, mais o manifest de hashes se couber sem nova dependência (SHA-256 da stdlib) |
| Dependências | P0-2 |
| Mudança | Arquivos no projeto-alvo. Sem novo backend |
| Aceite | Cenários 2, 3, 6, 7 passam no fixture. Página sem fonte não fica `status: atual`. Código divergente não é “corrigido” dentro da wiki em silêncio |
| Métricas | Paths lidos; acerto do verificador; 0 páginas `atual` cujo hash citado mudou. Tokens se P0-3 existir |
| Testes | Fixture do arquivo 08 |
| Riscos | Wiki gigante na primeira sessão. A skill já manda memória mínima. O teste deve falhar se a init criar dezenas de pastas |
| Esforço | Médio |
| Bloqueio | Se a operação exigir vector DB, parar |
| Concluída quando | Os quatro workflows (init, query, update, lint) têm uma corrida registrada no fixture |

### P1-2 — Retrieval com orçamento e dedup

| | |
|---|---|
| Problema | Nada impede reler o repo e colar a vault |
| Estado atual | Excerpt cap de 500 no parser wiki; sem orçamento de tarefa; sem dedup |
| Resultado | Procedimento: índice, até N páginas, `rg` até M paths, não reler path já na evidência. N e M saem do baseline ou, se P0-3 ainda não rodou, ficam como parâmetros do fixture (proposta inicial N=5 páginas, M=15 paths) e são recalibrados |
| Solução | Skill / checklist do agente. Se for para o engine, apenas contadores em evidência, aditivos |
| Dependências | P1-1 para o lado wiki; lexical não depende |
| Mudança | Evitar mudar `knowledge.search` v1. Um campo opcional de budget quebraria consumidores se for obrigatório. Preferir parâmetro de skill |
| Aceite | Cenário 10: braço com orçamento não perde o verificador e não lê o path canário |
| Métricas | Leituras redundantes = 0 para path já evidenciado. Tokens `NOT_MEASURED` até P0-3 |
| Testes | Contagem de leituras no log da run |
| Riscos | Orçamento corta a função no meio. Cortar por arquivo/símbolo inteiro, não por token no meio da linha |
| Esforço | Médio |
| Bloqueio | Se o host não reportar paths lidos, o dedup no engine não vê o agente Cursor. Nesse caso o aceite é o procedimento da skill mais um teste de laboratório, e o gap do host fica escrito |
| Concluída quando | O fixture mostra a lista de paths e a ausência do canário |

### P1-3 — Evidência de retrieval sem segredo

| | |
|---|---|

## P2 — Melhorias condicionadas ao bench

### P2-1 — Graphify só código

| | |
|---|---|
| Problema | Cadeia de dependência custa muitas leituras. Hipótese, não fato local |
| Estado | Ferramenta ausente. Release upstream v0.9.93 |
| Resultado | Flag de experimento. `graphify-out/` gitignored por raiz. Sem LLM, sem `--wiki`, sem cloud |
| Solução | CLI externa Apache-2.0, não importada no core |
| Dependências | P0-3 e P1-2. Python 3.10+ no ambiente de experimento |
| Mudança | Nenhuma no contrato se ficar fora do `KnowledgeBackend` |
| Aceite | Cenário 5 e 11: B3 vence B0 em dependentes e não perde para B1 em tokens totais; aresta usada na resposta é EXTRACTED ou está rotulada INFERRED; `--update` depois da mudança |
| Métricas | As do arquivo 08. Sem vitória, a flag fica off e a recomendação passa a DESCARTAR |
| Testes | O próprio bench |
| Riscos | Skill upstream manda não abrir arquivo. O experimento tem de instruir o contrário quando a citação não bater com o disco |
| Esforço | Médio |
| Bloqueio | Licença deixar de ser Apache; binário exigir rede; passagem LLM impossível de desligar |
| Concluída quando | Relatório do bench com decisão INTEGRAR-flag ou DESCARTAR. “Instalado” não é conclusão |

### P2-2 — Estilo de saída curto no host

| | |
|---|---|
| Problema | Prosa longa na resposta |
| Estado | Não há skill Caveman no pack do EvolveLoop |
| Resultado | Opcional, desligada por default. Proibida em mensagens que carregam comando, JSON, diff ou gate |

| Testes | Cenário 9 |

| Esforço | Baixo para ligar; médio para medir direito |

### P2-3 — Prompt cache no adapter, se existir adapter

| | |
|---|---|
| Problema | Prefixo estável é a forma de baixar custo sem apagar informação |
| Estado | Engine não chama o modelo nos testes live (`NOT_MEASURED`). Doc Anthropic descreve o mecanismo |
| Resultado | Se um provider HTTP próprio entrar no caminho, prefixo estável antes do breakpoint e retrieval depois |
| Solução | Não inventar cache para o IDE |
| Dependências | Um adapter real |
| Mudança | Aditiva no adapter |
| Aceite | Cache hit reportado pelo provedor em duas chamadas com o mesmo prefixo; uma mudança no bloco dinâmico não precisa invalidar o prefixo |
| Métricas | Tokens cacheados vs não cacheados, números do provedor |
| Testes | Duas chamadas gravadas |
| Riscos | Guardar prompt com segredo no cache do vendor. Não colocar segredo no prefixo |
| Esforço | Alto se o adapter não existe; baixo se existir |
| Bloqueio | Adapter ausente → permanece `NOT_MEASURED`, não simular |
| Concluída quando | O provedor mostra hit, ou o item é adiado com essa frase |

## Condições que não se trocam por token

Verificador da tarefa, literal de path/negação/comando, isolamento entre raízes, fail-closed da vault ausente, evidência sem segredo, código como fonte de verdade acima da wiki e do grafo.
